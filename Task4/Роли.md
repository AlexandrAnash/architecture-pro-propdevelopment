# Задание 4. Ролевой доступ к Kubernetes

Namespace'ы повторяют доменную структуру компании: `sales`, `tenant`, `finance`, `data`.

| Роль | Права роли | Группы пользователей |
|---|---|---|
| `propdev-viewer` (ClusterRole) | get / list / watch всех ресурсов во всех namespace'ах, **кроме secrets**. | `propdev:viewers` — владельцы продуктов, бизнес-аналитики, менеджеры операционных команд, аналитики BI |
| `propdev-domain-developer` (ClusterRole, выдается через RoleBinding в namespace домена) | В своём namespace: деплой приложений — deployments, statefulsets, pods, services, configmaps, jobs, ingresses, hpa; logs, exec, port-forward. Secrets — только create/update (записать можно, прочитать нельзя). RBAC и NetworkPolicy менять нельзя | `propdev:sales-dev`, `propdev:tenant-dev`, `propdev:finance-dev`, `propdev:data-dev` — разработчики и DevOps функциональных команд домена |
| `propdev-cluster-operator` (ClusterRole) | Настройка кластера: namespaces, nodes, PV, storageclasses, CRD, ingressclasses, networkpolicies, resourcequotas, limitranges; всё в workloads во всех namespace'ах. Secrets — **не читает**. RBAC не меняет | `propdev:platform` — инженеры эксплуатации платформы |
| `propdev-secrets-reader` (ClusterRole) | Привилегированная: get / list / watch secrets во всех namespace'ах. Больше ничего | `propdev:security` — специалист по ИБ |
| `propdev-rbac-admin` (ClusterRole) | Управление roles, rolebindings, clusterroles, clusterrolebindings, serviceaccounts. Привилегированная | `propdev:security` — ИБ согласует выдачу прав (проблема из описания: ИБ узнаёт не обо всех изменениях) |
| `cluster-admin` (встроенная) | Всё | `propdev:break-glass` — аварийный доступ, вход фиксируется в аудите (Task6). Постоянно в группе никого нет |

Пользователи для примера:

| Пользователь | Группа | Роль |
|---|---|---|
| `anna.viewer` | `propdev:viewers` | propdev-viewer |
| `petr.sales` | `propdev:sales-dev` | propdev-domain-developer в `sales` |
| `oleg.platform` | `propdev:platform` | propdev-cluster-operator |
| `irina.security` | `propdev:security` | propdev-secrets-reader, propdev-rbac-admin |

Скрипты (запускать по порядку на чистом minikube):
1. [create-users.sh](create-users.sh) — сертификаты и контексты kubeconfig
2. [create-roles.sh](create-roles.sh) — namespace'ы и ClusterRole
3. [bind-roles.sh](bind-roles.sh) — привязки групп к ролям + проверка через `kubectl auth can-i`
